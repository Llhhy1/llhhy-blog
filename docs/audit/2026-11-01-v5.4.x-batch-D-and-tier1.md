# v5.4.x 批次 D + 档 1：主题校验与访客自选主题

日期：2026-11-01　对应：`docs/audit/2026-10-31-v5.3.3-audit-and-theme.md` 的「批次 D」与「四档升级方案 · 档 1」
分支：`feat/theme-validation-and-picker`（两个 commit：批次 D 加固、档 1 访客选择器）

## 一、这两块合起来解决什么

审计里 4 个 P2 的共同点是「值会被原样搬进 CSS/XML 上下文」，而**开放访客自定义主题**
把这条路的入口从「只有超管能碰」扩大到「任何访客都能碰」。所以顺序是硬的：
先做批次 D（校验与白名单），档 1 才有安全前提；反过来做等于把注入面交给陌生人。

| 面 | 之前 | 现在 |
|---|---|---|
| `custom_css` | 只转义小写 `</style`，`</StYlE><script>…` 可逃逸出 `<style>` | `utils.css_context_escape()` 大小写不敏感；写入侧另拒一次 `</` |
| `accent_color` | 原样拼进 SSR `--accent: {{ … }}`，可注入任意 CSS 规则 | `themes.validate_accent()` 写入校验 + 渲染前再洗（`accent_hex`） |
| 自定义主题 token | 只判 `light.accent` 存不存在，任意键值落库 | 键必须命中白名单、值必须匹配该键语法；非法 400 且回逐条文案；读侧 `current_theme()` 再洗一遍 |
| `post.lang` | 只 `strip()`，`x'><script>…` 能落库 | `normalize_lang()`（BCP 47 宽松子集）写入收敛 + 4 处输出转义 |
| 访客换肤 | 只有站主能改主题 | 站主开关（默认**关**）开放后，访客可在 14 套预设里挑，只存自己浏览器 |

## 二、上线要做的事（按顺序）

1. **前端必须重新构建**：`cd vue-frontend && npm ci && npm run build`，产物在 `_vite_build30/`。
   `package.py` 打的是这个目录而不是 `src`，只改源码不 build → 线上仍是旧页面，且不会报错。
2. 后端照常覆盖 + `update.sh`（会 `pip install -r requirements.txt`）。
3. **无 Alembic 迁移**：`allow_visitor_theme` 是一个 Setting KV，首次保存开关时才建行。
4. 开放给访客：后台 → 🎨 主题中心 → 「允许访客自选主题」→ 保存。关掉即刻失效（含访客残留的选择）。

## 三、行为变化（可能有存量脚本依赖，值得先看一眼）

- `POST /api/theme` 的 `custom` **变严**：未知 token 键、`url(...)`、`red` 这类颜色名、
  `12px; body{...}` 一律 400，`details` 数组逐条说明。以前会「静默收下并落库」。
  如果你有历史主题 JSON 想导入，先按 400 的文案清一遍。
- 自定义主题现在**补齐基准**：只传 `accent` 也会得到完整一套 token，
  且 `accent_hover/accent_soft/info/text_muted/text_faint` 按新主色重算（不再留着旧蓝色）。
- 库里已有的脏 token（备份还原、直接改库）**读取时即被剔除并回落基准**，不用手工清库。
- `post.lang` 白名单只作用于**写入**；存量脏值不迁移，靠输出转义兜住（feed/hreflang/OG 均已转义）。

## 五、不要动（留给下一档的护栏）

- `themes._BASE_LIGHT` 是前台运行时主题的唯一真相源，改它必须同步两份 `tokens.css`
  （已有 `test_base_light_matches_token_files` 钉住）。
- token 白名单 `_TOKEN_KIND` 与 `_BASE_LIGHT` 的键集必须一致；加新 token 记得同时登记类别，
  否则新 token 会被自家校验挡掉。
- 访客主题只进 `localStorage`。不要为了「跨设备同步访客主题」把它写进 cookie 或用户表 ——
  那会让一个纯显示偏好变成服务端状态，顺带引入 CSRF/隐私面。
- 档 2（主题商店 / 用户上传主题包）之前，必须先有「主题包签名或来源限制」，
  否则白名单只是把注入换成了任意值。
