# EdgeOne 真实访客 IP 还原 —— 腾讯云后台操作手册

> **这份文档是给站主（大帅）看的**：代码侧已由 Agent 改完（`utils/net.py` + `config.py`），
> **但必须你在腾讯云 EdgeOne 控制台和宝塔面板各做一次配置，功能才会生效**。
>
> 版本：v4.8.5 ｜ 更新：2026-10-24

---

## 0. 先看一眼：为什么要做这件事

站点套了腾讯 EdgeOne 后，请求链路变成：

```
浏览器 → EdgeOne 边缘节点 → Nginx → Gunicorn/Flask
```

**实测证据**（线上 `visit_log` 表 TOP IP）：

| IP | 访问次数 |
|---|---|
| `223.74.211.144` | 426 |
| `223.74.211.94` | 304 |
| `223.74.146.125` | 202 |
| `116.16.148.46` | 99 |

这些全是**腾讯云回源节点段**。单个 IP 426 次访问，明显是 CDN 节点把成千上百个访客合并成了一个 IP。

**后果**：访客记录、实时在线人数、基于 IP 的限流/防刷，全部失真。

**根因**（关键，决定了为什么不能只用标准开关）：
Nginx 配了 `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for`，它会**把 EdgeOne 节点 IP 追加到 XFF 末尾**。而 Flask 侧 `get_client_ip()` 取的是「XFF 最右端」——所以拿到的必然是节点 IP。

> ⚠️ **这意味着：只开 EdgeOne 的「客户端 IP 头部回源」是不够的。**
> 开了之后 XFF 会变成 `真实IP, 节点IP`，取最右端**还是节点 IP**。
> 所以必须用下面的「自定义头 + 共享密钥」方案。

## 1. 你要准备的东西（1 分钟）

### 生成一个共享密钥

这是一个只有你和 EdgeOne 知道的随机串。**自己生成一个**（任选其一）：

```bash
# 方式一：32 位十六进制（128 位熵，推荐）
python -c "import secrets;print(secrets.token_hex(16))"

# 方式二：URL-safe base64（22 字符）
python -c "import secrets;print(secrets.token_urlsafe(16))"
```

生成后先存在**只有你能看到的地方**（本地记事本 / 密码管理器），然后照下文填两处。

> 🔒 **为什么这份文档里不放真实密钥**
>
> 这份文档会进 git 仓库、会随 Release 发布。密钥一旦写进仓库，就等于公开了——
> 任何能 clone 仓库的人都能伪造 `X-EO-Auth` 头，把访客统计和限流全部打歪。
> 所以文档里只放**占位符**，真实值由你生成、只存在于：
> ① EdgeOne 控制台 ② 宝塔面板环境变量。
>
> ⚠️ 同理：**不要**把真实密钥贴回这份文档、不要写进任何 `.py` / `.js` / 前端代码、
> 不要发群。代码侧只从环境变量 `EO_AUTH_KEY` 读（见 `myblog/config.py`）。

## 2. 第一步：EdgeOne 控制台配置（必须做）

登录 **腾讯云 → EdgeOne**（边缘安全加速平台 EO），选中站点 `www.llhhy.cn`。

### 2.1 开启「客户端 IP 头部」（核心，一行就够）

**路径**：`站点加速` → `回源配置`（也可能在「站点全局配置 / 网络优化」下）

找到 **「客户端 IP 头部」**，**打开开关**。打开后页面会显示：

```
客户端 IP 头部                    [开]
自定义头部携带客户端 IP 信息回源站
头部名称：EO-Client-IP
```

**这个 `EO-Client-IP` 就是 EdgeOne 内置的回源头**，开关一开它自动带上，
**不需要规则引擎、不需要猜变量名**。代码侧已经认这个头。

> 同一页通常还有个「客户端 IP 地理位置头部」（`EO-Client-IPCountry`，两位国家码）。
> 本项目按 IP 自己解析属地，用不上，可不开。

### 2.2 （可选，进阶）再加一个密钥头防伪造

⚠️ **先看懂这个取舍再决定要不要做**：

只开 2.1 时，`EO-Client-IP` 是**可被伪造的** —— 任何知道源站 IP 的人，直连源站
给自己请求加一个 `EO-Client-IP: 1.2.3.4` 就能骗过统计，也能轮换假 IP 绕过限流。
代码侧在没配密钥时**仍然采纳**这个头（保统计准确性），但你要知道有这个风险。

两个补救办法，按推荐顺序：

**办法 A：拒绝直连源站（最简单，无需规则引擎）**

配好 `EO_AUTH_KEY` 后（见第 3 节），再开 `EO_BLOCK_DIRECT=true`。
但注意：这个开关靠 `X-EO-Auth` 识别，**而 `X-EO-Auth` 本身也需要规则引擎才能加**
（见办法 B）。所以办法 A 实际依赖办法 B，单独用不了。

**办法 B：用规则引擎加一个共享密钥头**

**路径**：`规则引擎` → `新建规则`，匹配范围选「全部请求」，
操作类型选「回源请求头」/「修改请求头」，加一条：

| 字段 | 值 |
|---|---|
| 头部名称 | `X-EO-Auth` |
| 头部值 | 你的密钥（直接手打，不用变量） |

保存并**发布**。这样代码侧就要求 `X-EO-Auth` 匹配才采纳 IP 头，**不可伪造**。

> 🔍 **找不到「回源请求头」这个操作？** 部分 EdgeOne 套餐不开放自定义回源头。
> 那就只能停留在「办法 A 之前的状态」：统计准确但可被伪造。
> → 告诉我，我改走备选方案 C：在 Nginx 只对 EdgeOne 回源 IP 段透传 `EO-Client-IP`，
>   其余一律删掉（需要维护回源段列表，腾讯会变）。

### 2.3 如果你找不到「客户端 IP 头部」

老版本界面里它可能叫「真实客户端 IP」/「传递客户端 IP」。
确实没有的话 → 告诉我，走备选方案 C。

## 3. 第二步：宝塔面板配环境变量（必须做）

代码从环境变量读密钥，**不配 = 功能不启用**（此时行为与改之前完全一致，不会有任何风险）。

**路径**：宝塔面板 → `网站` → `Python项目 myblog` → `环境变量`（或「项目配置」里的环境变量管理）

新增一条：

| 名称 | 值 |
|---|---|
| `EO_AUTH_KEY` | 第 1 节生成的密钥 |

保存后**重启项目**（环境变量要重启才生效）。

> ⚠️ 面板里 `vhost/env/myblog.env` 是它自动生成的文件，**别手改**，会被覆盖。
> 加变量就走面板（或让我用 `PythonProjectModify` 改 `env_list`，连带重启）。

## 4. 第三步：验证（重要）

配完后，按顺序验证。**每一步不通过就停，别继续。**

### 4.1 确认密钥确实在环境变量里

```bash
grep -c '^EO_AUTH_KEY=' /www/server/python_project/vhost/env/myblog.env
```
应输出 `1`。若为 `0`，说明第 3 步没生效，回去重启项目。

### 4.2 确认 Nginx 把自定义头透传给了 Flask

Nginx `proxy_pass` 默认透传所有客户端头，理论上 `EO-Client-IP` / `X-EO-Auth` 能到 Flask。
但**必须实测**。在服务器上跑：

```bash
curl -s -o /dev/null -w '%{http_code}\n' \
  -H 'X-EO-Auth: 第1节生成的密钥' \
  -H 'EO-Client-IP: 1.2.3.4' \
  http://127.0.0.1:8686/api/health
```

若返回 200，说明头已透传（这一步只验证「通不通」，不代表 EO 配好了）。
**若这一步失败**，说明 Nginx 拦了自定义头，需要我去改 vhost 加
`proxy_set_header EO-Client-IP $http_eo_client_ip;` 等行——告诉我，我来改。

### 4.3 等真实流量进来，看数据库

过几个小时（或你自己访问几次），查：

```bash
sqlite3 /www/wwwroot/myblog/data/blog.db \
  "select ip, count(*) c from visit_log group by ip order by c desc limit 10;"
```

**成功的标志**：TOP IP **不再是** `223.74.x.x` / `116.16.x.x`，而是分散的真实公网 IP，
且单个 IP 的访问次数从几百降到几十。

### 4.4 后台页面对照

后台「访客记录 / 统计」页面，属地应该开始出现真实的省级/市级分布，而不是几个固定机房。

## 5. 第四步（可选，默认别开）：拒绝直连源站

代码里有个加固开关 `EO_BLOCK_DIRECT`：开启后，没带正确 `X-EO-Auth` 的请求直接 403，
防止攻击者绕过 CDN 直连源站 IP 打你。

**⚠️ 默认关闭，且我建议你确认第 4 步全部通过后再开。**

原因：一旦 EdgeOne 侧漏配规则、某类回源没带头、或缓存命中路径没回源，**全站会 403**。
对个人博客这是不可接受的故障面。

确认无误后要开的话：

| 名称 | 值 |
|---|---|
| `EO_BLOCK_DIRECT` | `true` |

已内置放行：`/.well-known/`（证书续期）、`/api/health`（健康检查）、`OPTIONS` 预检。
没配 `EO_AUTH_KEY` 时这个开关自动失效（不会把自己关在门外）。

## 6. 历史脏数据怎么办

`visit_log` 里已有的约 4708 行节点 IP 记录会污染统计。

**我没有自动删**——这是不可逆操作，要你点头。三个选项：

| 选项 | 做法 | 适合 |
|---|---|---|
| A. 不管 | 保留，新数据自动是真实 IP | 你不在意历史曲线 |
| B. 标记 | 加个迁移脚本，把已知节点段的 `is_bot` 置 1 或打标 | 想保留但排除出统计 |
| C. 清空重来 | 备份后 `delete from visit_log` | 统计刚起步，不在乎历史 |

> 选 B 或 C 告诉我，我写脚本（会先备份，走 `/tmp` → `su www` → checkpoint → chown 那套）。

## 7. 故障排查速查

| 现象 | 最可能原因 | 怎么办 |
|---|---|---|
| 配了却没变化，还是节点 IP | `EO_AUTH_KEY` 没配/没重启 | 回第 3 步，确认 4.1 输出 1 |
| 同上 | EdgeOne 规则没匹配到请求 | 检查规则范围是否「全部请求」 |
| 同上 | 值栏变量选错了，回过去的是空 | 重新选「客户端 IP」变量 |
| 全站 403 | 开了 `EO_BLOCK_DIRECT` 但 EO 没配对 | 先把 `EO_BLOCK_DIRECT` 删掉/设 false |
| 4.2 那步就失败 | Nginx 不透传自定义头 | 告诉我，我改 vhost |
| 后台打不开 | 同上，403 波及 `/admin` | 关掉 `EO_BLOCK_DIRECT` |

## 附：代码侧改了什么（备查，不用你操作）

| 文件 | 改动 |
|---|---|
| `myblog/config.py` | 新增 `EO_AUTH_KEY` / `EO_BLOCK_DIRECT` 两个配置项（读环境变量） |
| `myblog/utils/net.py` | `get_client_ip()` 新增第 0 级 EO 头（`EO-Client-IP` 内置 + `X-EO-Client-IP` 备选）；新增 `_clean_ip()` 做 IP 合法性归一 |
| `myblog/app.py` | 新增 `enforce_edgeone_only()` 钩子（`EO_BLOCK_DIRECT` 开时才拦，默认放行） |
| `tests/test_edgeone_client_ip.py` | 28 项守卫测试（含伪造攻击、向后兼容、脏值归一） |

**安全模型（分两种配置状态，别混）**：

| 状态 | 行为 | 风险 |
|---|---|---|
| 只开 EdgeOne 开关，**没配** `EO_AUTH_KEY` | 采纳 `EO-Client-IP` | ⚠️ 该头可被直连源站者伪造 → 限流可被轮换假 IP 绕过。**换统计准确性** |
| 配了 `EO_AUTH_KEY` + 规则引擎加了 `X-EO-Auth` | 要求密钥匹配才采纳 | ✅ 不可伪造（攻击者猜不到密钥） |

没配密钥时**不会**退回旧行为（旧行为是节点 IP，统计全废），这是刻意的——
否则这个功能在最常见的配置下根本不生效。若要「不可伪造」，按 2.2 配密钥头，
或让我上 Nginx 回源段过滤（备选方案 C）。
