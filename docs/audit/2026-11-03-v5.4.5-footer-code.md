## 二、上线：自定义页脚代码（`footer_html`）

### 2.1 它解决什么

站主想在页脚放**自己写的 HTML**：统计代码、自定义链接、版权行。既有的 `footer_text`（纯文本）
与 `beian_code`（备案号，且固定链到 beian.miit.gov.cn）都承担不了这个。

### 2.2 取舍：不清洗内容，改收「谁能写 / 写多大 / 有没有留痕」

清洗（转义 `<`、剥掉 `<script>`）会让头号用途直接失效，所以**刻意不做**，改为三道边界：

1. **谁能写**：唯一入口是 `myblog/admin/settings.py` 的 `POST /admin/settings`，整个路由是
   `@super_required`。普通管理员 403；`/api/*` 没有任何能写这个键的端点（移动端
   `api/mobile_ops.py` 的 `_SETTING_KEYS` 是**只读**展示白名单，`footer_html` 刻意没进去）。
2. **写多大**：`admin/settings.py` 顶部 `FOOTER_HTML_MAX = 20000`（字符）。超限**拒绝并保留原值**，
   其它字段照常保存 —— 与本项目既有「一个字段填错不丢整张表单」的纪律一致。
   这个值会进**每一个前台页面**的响应体，上限防的是误粘贴整份 HTML。
3. **留痕与回滚**：值真的变化时记一条 `log_audit("settings", target="自定义页脚代码", …)`
   （含字符数或「已清空」）；值没变**不刷**日志。字段同时在 `fields` 列表里 → 自动进
   `config_rollback` 配置快照，可回滚。

### 2.3 渲染路径（两处，行为不同，别改错边）

| 路径 | 位置 | 写法 | CSP 后果 |
|---|---|---|---|
| SSR 页脚 | `myblog/templates/base.html` 第 150 行 | `{{ settings.footer_html \| safe }}` | Flask 渲染的页面带 `script-src 'self' 'unsafe-inline' 'unsafe-eval'` → **内联脚本能跑，站外 `<script src>` 被拦** |
| SPA 页脚 | `vue-frontend/src/App.vue` 第 187 行 `<div id="site-footer-code">` + `store.js` `injectFooterCode()` | 原生 DOM 注入并**重建 script 节点** | SPA 首页由 nginx 直出、**不带 CSP 头** → 内联与站外脚本都能跑，统计代码在这条路径上工作 |

**为什么 SPA 不能用 `v-html`**：按 HTML 规范，经由 `innerHTML` 插入的 `<script>` **不会执行**。
用 `v-html` 的结果是「贴上去没报错、也真的看不见，但统计永远 0 条」——最难查的一类问题。
所以 `injectFooterCode()`（`store.js` 第 298 行起）在插入后把每个 `<script>` 换成新建元素
（属性照抄，内联补 `textContent`，外链靠 `src` 自然加载），并用容器上的 `data-src` 做**幂等比对**：
SPA 切路由不会重复执行（否则每换一次页 PV 就多算一次）。

### 2.4 接口契约

- `GET /api/site` **新增** `footer_html`，**恒有该键**（未配置为 `""`），前端据此区分「没配」与「配了空」。
- `GET /api/theme`、`POST /api/theme`、`GET /api/site` **移除** v5.4.3 引入的 `allow_visitor_theme`；
  `POST /api/theme` **移除** `visitor_theme` 入参 —— 老客户端再提交它会被**静默忽略**（不报错、不写库）。
- 后台无新增页面；「站点设置 → ① 站点信息」在页脚文字/备案号下面多一个 textarea。

## 四、不要动（合并时最容易顺手改的地方）

1. **不要恢复档 1**，也不要「顺手补个访客主题开关」。缺席守卫会红，红是对的。
2. **不要把 `footer_html` 接到任何 `/api/*` 写端点或移动端白名单**。它现在的唯一写入口是超管表单；
   多一个入口就多一条绕过 CSRF/审计的路。
3. **不要给 `footer_html` 加 bleach/DOMPurify 清洗**，也不要改成 `v-html`。前者砍掉统计代码，
   后者让脚本静默不执行。
4. **不要动 `tests/test_album.py` 里那 3 条 SIM115**，也不要用 `--update` 放宽 `tools/lint_debt.py`
   基线（合计 256）。棘轮只允许往下。
5. **不要为外链统计脚本放宽 CSP**（`script-src` 加 `https:`）。SPA 路径本来就不带 CSP，
   放宽只会把 Flask 渲染的后台/登录页一起放开，收益为零。
6. **不要加数据库迁移**。`footer_html` 是 Setting KV，`_ensure_settings()` 补的是默认空值行。

## 五、部署与验收

1. `cd vue-frontend && npm ci && npm run build`（产物 `_vite_build30/`；`package.py` 打的是这个目录，
   只改源码不 build → 线上还是旧页面，**并且不会报错**）。本轮删了一个组件文件，务必确认产物里不再有它。
2. 后端包照常覆盖 → gunicorn「停止 → 启动」。**无迁移、无新依赖**。
3. 手工验收（这是「不生效最难查」的功能，必须真点一次）：
   - 后台 → ⚙️ 站点设置 → 「自定义页脚代码」填 `<script>console.log("footer-ok")</script>` → 保存；
   - 硬刷新前台首页 → 控制台出现 `footer-ok`；**在站内来回切路由不应重复打印**；
   - 再填一段 `<p>页脚测试</p>` → 前台页脚与 `/login` 页脚都应出现这行；
   - 贴一个站外统计 `<script src="https://…">` → **在前台**应能看到该请求发出（在登录页会被 CSP 拦，属预期，别在那儿验）；
   - 后台 → 🎨 主题中心：不应再有「允许访客自选主题」卡片；前台顶栏与手机抽屉不应再有「🎨 选择主题」按钮。
4. 门禁：`pytest` 全量、`ruff check`、`python tools/lint_debt.py`（**不带 `--update`**）、
   `python tools/check_i18n.py`、`npm run build`。
